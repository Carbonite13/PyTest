# WebRTC and transcript protocol

The system uses browser-to-browser WebRTC. FastAPI relays signaling messages;
it is not an SFU or MCU. See [endpoints.md](endpoints.md) for wire examples.

## Connection sequence

1. `POST /rtc/sessions` creates a `waiting` meeting and returns a meeting code
   plus a private host capability.
2. Each browser opens `/rtc/ws` and receives a random peer ID.
3. The host sends `join.join` with the session ID and host capability. A guest
   sends the same message without the capability and waits for admission.
4. The server sends `room_info`; existing members receive `peer_joined`.
5. Existing members initiate offers. SDP and trickle ICE are relayed only to
   admitted peers in the same room.
6. The browser queues ICE candidates until the matching remote description is
   installed. Connection-state failures trigger an ICE restart.

Signaling connectivity and media connectivity are separate. The client reports
the `RTCPeerConnection.connectionState`; an open WebSocket alone is not treated
as a working audio/video connection.

Meeting-code holders are admitted automatically while the session is active.
The host capability remains separate: it is required for ending the meeting
and for changing host ownership after a reconnect. This avoids blocking
normal participants behind a host-admission prompt without removing lifecycle
authorization.

## Transcript event schema (protocol version 1)

```text
event_id         unique client event ID, used for deduplication
meeting_id       session/room ID; must match the authenticated socket's room
participant_id   authenticated WebSocket peer ID; arbitrary IDs are rejected
session_id       local ASR/transcription session ID
sequence_number  monotonically increasing per participant + ASR session
event_type       partial | final | status | error
text             optional for status/error, max 4000 characters otherwise
start_time       optional seconds relative to local ASR/media origin
end_time         optional seconds relative to local ASR/media origin
created_at       RFC3339 timestamp generated by the client
protocol_version literal "1"
```

The backend bounds WebSocket payloads and per-meeting events, rejects invalid
timing and empty transcript text, deduplicates event IDs, replaces partials by
participant/session/sequence, and commits finals without the old partial. It
does not infer missing timestamps or reorder speech based on network arrival.
Transcript authorization also requires the socket to be admitted in the room
and the peer ID to be registered in the corresponding meeting session. After
reconnection the browser receives a new peer ID; queued events are rebound to
that current authenticated ID and are flushed only after the replacement
socket receives `room_info`. This prevents stale events from being rejected or
sent before admission.

## ASR and privacy

`Tea/js/modules/transcription.js` contains an adapter interface and an opt-in
browser-native adapter. Web Speech processing is not reliably identifiable as
offline across browsers, so strict local/offline transcription cannot be
verified in this repository without an offline engine and target-browser test.
The default meeting path therefore sends no raw audio; integrating a local
WebAssembly/native ASR engine should implement the same adapter callbacks.
